# Jaiylym — пастбища села по спутнику

**Сайт:** https://ainara001.github.io/jaiylym/ · **Бот для пастуха:** [@JAIYLYM_bot](https://t.me/JAIYLYM_bot)

Jaiylym помогает селу распределить скот по пастбищам так, чтобы ни один участок не был перегружен,
и показывает акимату, где новый водопой откроет больше всего корма. Проект для SPARK Startup Hackathon
(направление GreenTech & Sustainability). Интерфейс на русском и казахском.

## Разделы сайта

| Раздел | Что там |
|---|---|
| **Главная** | Объяснение ценности, поиск села, пример (Кеген) с реальными данными |
| **Карта** | Карта участков (режимы «Сейчас», «План», «Трава»), панель анализа: обзор (до и после, диаграмма и две схемы), стада, маршруты, водопои (моделирование), таблица участков с достоверностью, источники данных. Кнопки: сохранить сценарий, PDF-отчёт, открыть село в боте, опубликовать план села (координатор) |
| **Сценарии** | Свои сценарии, планы акимата для своего села, история расчётов |
| **Профиль** | Вход через Telegram, профиль хозяйства (село, поголовье, домашний и доступные участки), выход, удаление аккаунта |
| **Координатор** | Сёла координатора, хозяйства в них, совместный план. Видно только с ролью координатора |
| **О данных** | Что измерено спутником, что ввёл пользователь, что является допущением модели. Как считается достоверность |

Каждое число в интерфейсе помечено источником: **Спутник** (измерение Sentinel-2 / WorldCover),
**Ввод** (поголовье, водопои, цена сена), **Модель** (ёмкость, нагрузка, тонны сена, стоимость).
Стоимость сена — оценка модели, а не доказанная экономия.

## Вход и роли

Паролей нет. Вход через Telegram:
1. сайт запрашивает у сервера одноразовый код (`POST /auth/start`) и показывает его;
2. человек открывает бота по ссылке, бот показывает тот же код и кнопки «Подтвердить вход» / «Отмена»;
3. сайт получает токен сессии (`GET /auth/poll`). На сервере хранится только SHA-256 токена, срок 30 дней. Выход удаляет сессию.

Личность подтверждает Telegram: нажатие кнопки приходит на сервер через webhook, защищённый секретом.
В браузере хранится только токен сессии (не пароль). Гость может пользоваться картой, расчётами,
сценариями и PDF без входа, сценарии гостя хранятся в его браузере.

Роли проверяются на сервере при каждом запросе (`api.js`):
- **фермер** — любой вошедший: свой профиль, свои сценарии и история; видит планы акимата своего села;
- **координатор** — Telegram ID указан в переменной окружения `COORDINATOR_IDS` на Render (через запятую):
  добавляет сёла, видит хозяйства только этих сёл, публикует общий план села.

Чтобы назначить координатора: Render → `jaiylym-bot` → Environment → `COORDINATOR_IDS` = `123456789,987654321` → Save.
Свой Telegram ID человек видит в профиле на сайте.

Профиль хозяйства связан с ботом: стадо из профиля сразу участвует в расчёте села и в маршрутах бота.

## Как это работает

| Файл | Что делает |
|---|---|
| `web/pipeline.js` | Поиск места (OpenStreetMap), снимки Sentinel-2 и ESA WorldCover (Microsoft Planetary Computer), NDVI и пастбища на 16 участках, график NDVI по снимкам. Работает в браузере и в боте, без ключей |
| `web/engine.js` | Алгоритм: корм → ёмкость → нагрузка → план → водопои (не менялся) |
| `web/index.html`, `web/css/app.css` | Интерфейс |
| `web/js/app.js` | Логика интерфейса: карта, панели, сценарии, профиль, координатор |
| `web/js/i18n.js` | Тексты на русском и казахском (казахский перевод стоит проверить носителю языка) |
| `web/js/client.js` | Связь с сервером: вход, профиль, сценарии, история |
| `web/js/report.js` | PDF-отчёт (html2pdf.js; без сети — печать «Сохранить как PDF») |
| `web/sw.js` | Офлайн-кэш интерфейса и примера |
| `api.js` | Серверное API: вход, сессии, роли, профили, сценарии, история, координатор |
| `bot.js` | Telegram-бот, webhook, подтверждение входа, ежедневная проверка |
| `store.js` | Хранилище: Render Key Value (Redis) или файл |
| `ndvi.py` | Расчёт села на Python с разрешением 20 м и сравнением с 2019 годом (им посчитан Кеген) |

Формулы (без нейросетей):
- биомасса, кг/га = (NDVI − 0,10) × 4000 — **коэффициент нужно откалибровать укосом** (срезать траву с 1 м² на 3–5 участках, высушить, взвесить);
- доступный корм = пастбище, га × биомасса × 0,5;
- 1 условная голова съедает ≈ 11 кг сухого корма в сутки; КРС и лошадь = 1, овца и коза = 0,2;
- план: дойные стада только на ближних участках; отары сначала на дальние участки с водой; нигде не больше 100 %.

Достоверность участка (относится к спутниковому показателю): высокая — от 4 безоблачных снимков и от 100 га пастбища;
средняя — 2–3 снимка; низкая — меньше 2 снимков, меньше 20 га или нет NDVI.

## Запуск у себя

```bash
python3 -m http.server 8765 --directory web          # сайт → http://localhost:8765
```

Бот и API: файл `.env` (не попадает в git) с `TELEGRAM_TOKEN=…` и по желанию `GEMINI_API_KEY=…`, затем `node bot.js`.
Пока бот работает на Render, локально его не запускайте: локальный запуск отключает webhook.

## Хостинг

- Сайт — GitHub Pages из ветки `gh-pages` (обновляется при каждом push в `main`).
- Бот и API — Render (`render.yaml`): веб-сервис + Key Value. Бесплатный сервер засыпает через 15 минут, первый ответ после паузы — до минуты.
- **Важно:** бесплатный Key Value на Render может потерять данные при перезапуске хранилища (аккаунты, профили, сценарии). Для реального использования нужен платный тариф с сохранением на диск или база данных.
- Ежедневная проверка снимков — `.github/workflows/daily-check.yml`, нужен пароль `CRON_SECRET` в Render и в GitHub Secrets.

## Что реальное, а что условное

**Реальное:** NDVI по снимкам Sentinel-2, маска пастбищ ESA WorldCover, площади пастбищ, поиск сёл, расчёт по формулам выше, вход через Telegram и роли на сервере.

**Условное:** границы участков (секторы; в реальности — схема пастбищ акимата), демо-стада в Кегене,
вода на дальних участках (по водоёмам на карте), коэффициент биомассы, цена сена (30 000 ₸/т — пример).

**Кеген, 2019 → 2026:** NDVI на ближних участках почти не изменился (−0,01), на дальних вырос (+0,03).
Это похоже на перевыпас у села, но двух лет мало для вывода: нужен ряд за 5–8 лет и проверка на месте.
