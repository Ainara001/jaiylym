# Jaiylym — пастбища села по спутнику

**Сайт:** https://ainara001.github.io/jaiylym/ · **Бот для пастуха:** [@JAIYLYM_bot](https://t.me/JAIYLYM_bot)

Jaiylym показывает со спутника, где у села есть трава и на сколько дней её хватит, делит пастбище между
хозяйствами и общими стадами и помогает им договориться до сезона (Келісім). Проект для SPARK Startup Hackathon
(направление GreenTech & Sustainability). Интерфейс на русском и казахском.

## Разделы сайта

| Раздел | Что там |
|---|---|
| **Главная** | Объяснение ценности, поиск села, готовые примеры (Бесколь, Кеген) с реальными данными |
| **Карта** | Карта участков (режимы «У села», «План», «Трава»), панель анализа: обзор (до и после, диаграмма и две схемы), стада, маршруты, водопои (моделирование), таблица участков с достоверностью, источники данных. Кнопки: сохранить сценарий, согласовать с людьми, PDF-отчёт, открыть село в боте |
| **Келісім** | Согласование плана: участники — хозяйства и общие стада, отвечает хозяин или пастух по личной ссылке; протокол PDF |
| **Келісім: карта и чат** | Общая карта: каждый участник ставит кружок «хочу пасти здесь» (свой цвет у каждого), остальные видят, голосуют 👍/👎 и обсуждают в чате рядом; видно, кто в сети и кто ещё не открывал ссылку. Плюсы и минусы места — по расчёту (трава, вода, ёмкость, кто ещё здесь, нагрузка, путь), ИИ даёт оценку и совет, перед подтверждением — «Вы уверены?»; сводка мест и общая оценка ИИ |
| **Сценарии** | Свои сценарии, история расчётов |
| **Профиль** | Вход по паролю или через Telegram, профиль хозяйства (село, поголовье, домашний и доступные участки), выход, удаление аккаунта |
| **О данных** | Что измерено спутником, что ввёл пользователь, что является допущением модели. Как считается достоверность |

Каждое число в интерфейсе помечено источником: **Спутник** (измерение Sentinel-2 / WorldCover),
**Ввод** (поголовье, водопои, цена сена), **Модель** (ёмкость, нагрузка, тонны сена, стоимость).
Стоимость сена — оценка модели, а не доказанная экономия.

## Вход и роли

Два способа на выбор — Telegram не обязателен:

**Логин и пароль** (`POST /auth/register`, `POST /auth/login`): логин — телефон Казахстана (приводится к `+7…`), e-mail или имя латиницей;
пароль от 8 знаков, на сервере хранится только хэш scrypt с солью. Неверный пароль и неизвестный логин дают один и тот же ответ;
после 10 неверных попыток с одного адреса (50 со всех) логин закрыт на 15 минут, частота регистраций и входов ограничена по адресу.

**Telegram** — без пароля, с уведомлениями в боте:
1. сайт запрашивает у сервера одноразовый код (`POST /auth/start`) и показывает его;
2. человек открывает бота по ссылке, бот показывает тот же код и кнопки «Подтвердить вход» / «Отмена»;
3. сайт получает токен сессии (`GET /auth/poll`). На сервере хранится только SHA-256 токена, срок 30 дней. Выход удаляет сессию.

Личность подтверждает Telegram: нажатие кнопки приходит на сервер через webhook, защищённый секретом.
В браузере хранится только токен сессии (не пароль). Гость может пользоваться картой, расчётами,
сценариями и PDF без входа, сценарии гостя хранятся в его браузере.

Доступ проверяется на сервере при каждом запросе (`api.js`): человек видит и меняет только своё.

Профиль хозяйства связан с ботом: стадо из профиля сразу участвует в расчёте села и в маршрутах бота.

## Понятная сводка и ИИ-помощник

- Вкладка **«Главное»** на карте объясняет ситуацию простыми словами: хватает ли пастбищ, сколько овец они прокормят,
  на сколько дней хватит корма каждому стаду и почему, что сделать (3–4 шага), где нужен водопой, ближайшие перегоны и погода
  (Open-Meteo: осадки за 30 дней и прогноз на неделю). Подробные расчёты — под кнопкой «Расчёты подробно».
- **ИИ-помощник** (DeepSeek, запасной вариант — Gemini) — кнопка «Объяснить с ИИ» и отдельный чат. Сайт отправляет на сервер данные открытого села
  (участки, NDVI, стада, план, погода), сервер спрашивает модель: `ai.js` выбирает `deepseek.js` при `DEEPSEEK_API_KEY` (иначе `gemini.js`,
  либо явно `AI_PROVIDER=deepseek|gemini`). Ключ хранится только на сервере.
  Ограничения: 12 вопросов в минуту с одного адреса и дневной лимит (`AI_DAILY_LIMIT`, по умолчанию 1500).
  Старый метод Google `generateContent` для новых ключей отвечает пустым 404 — поэтому раньше бот «не помогал».
- **Настройки** (язык, режим карты, демо-стада, параметры модели, очистка данных) и раздел **«Что это»** (как пользоваться, словарь, частые вопросы, источники данных).

## Свои пастбища

Фермер рисует границы своего участка на карте (кнопка «Нарисовать пастбище», точки по углам, «Готово»; на телефоне — пальцем).
Сайт считает по снимкам Sentinel-2 **внутри границ**: площадь, состав по ESA WorldCover (пастбищный покров — те же классы,
что у участков села; исключено — лес, пашня, застройка, вода; неясно), NDVI по пастбищным пикселям (медиана безоблачных
летних снимков), график NDVI по снимкам, качество снимка, ёмкость за сезон и нагрузку своего стада.
Гость видит расчёт; сохранить пастбище в профиль можно после входа (до 10 пастбищ). Площадь сервер пересчитывает сам.
Кнопка «Уведомления в Telegram» подписывает владельца на это пастбище:
в сезон бот присылает NDVI по каждому новому снимку и предупреждает, если трава убывает.

Границы — ввод фермера, а не кадастр; на сайте так и помечено.

## Как это работает

| Файл | Что делает |
|---|---|
| `web/pipeline.js` | Поиск места (OpenStreetMap), снимки Sentinel-2 и ESA WorldCover (Microsoft Planetary Computer), NDVI и пастбища на 16 участках, график NDVI по снимкам. Работает в браузере и в боте, без ключей |
| `web/model.js` | Параметры модели (единицы, диапазоны, источник, слои «стандарт / калибровка / свои»), версия модели, правила качества снимка и достоверности корма, статусы воды, единые метаданные |
| `web/zone.js` | Где селу можно пасти: контур, гектары по документам или вся трава вокруг |
| `web/engine.js` | Алгоритм: корм → ёмкость → нагрузка → план (статус, причины, предложения) → водопои, «Что если?», точная граница |
| `web/index.html`, `web/css/app.css` | Интерфейс |
| `web/js/app.js` | Логика интерфейса: карта, панели, сценарии, профиль |
| `web/js/i18n.js` | Тексты на русском и казахском (казахский перевод стоит проверить носителю языка) |
| `web/js/client.js` | Связь с сервером: вход, профиль, сценарии, история |
| `web/js/report.js` | PDF-отчёт (html2pdf.js; без сети — печать «Сохранить как PDF») |
| `web/sw.js` | Офлайн-кэш интерфейса и примера |
| `api.js` | Серверное API: вход, сессии, профили, сценарии, история |
| `bot.js` | Telegram-бот, webhook, подтверждение входа, ежедневная проверка |
| `web/js/kelisim-live.js` | Келісім: общая карта и чат (кружки участников, голоса, кто в сети, оценка ИИ, сводка); данные — `GET /api/kelisim/<id>/live`, `POST …/pin`, `…/chat`, `…/assess`, `…/summary` |
| `kelisim.js`, `web/kelisim.js`, `web/js/kelisim-ui.js` | Келісім: согласование плана (участник — хозяйство или общее стадо) — сервер, расчёт последствий, экраны организатора и двора |
| `store.js` | Хранилище: Render Key Value (Redis) или файл |
| `ndvi.py` | Расчёт села на Python с разрешением 20 м и сравнением с 2019 годом (им посчитан Кеген) |

Формулы (без нейросетей), модель версии **2.3.0**, полевыми измерениями **не подтверждена**. Подробно — `docs/METHODOLOGY.md`:
- биомасса, кг/га = max(0, NDVI − 0,10) × 4000 — **коэффициент нужно откалибровать укосом** (срезать траву с 1 м² на 3–5 участках, высушить, взвесить);
- доступный корм = пастбище, га × биомасса × 0,5;
- 1 условная голова съедает ≈ 11 кг сухого корма в сутки; КРС = 1, лошадь = 1,2, овца и коза = 0,2;
- ёмкость участка — **меньшее** из оценки по снимку и предельной нормы нагрузки Минсельхоза (приказ № 3-3/332, `web/norms.js`);
- нет NDVI → ёмкость **неизвестна** («нет данных»), а не ноль; такой участок не попадает в план;
- план — **справедливая оптимизация** (по умолчанию): у всех хозяйств одинаковая доля обеспеченности, насколько позволяют
  ограничения; при этом максимум корма (равен точной границе max-flow) и минимум перегона. Дойные стада сначала на ближних
  участках; только участки хозяйства (если указаны), без закрытых; нигде не больше 100 %. Если всех разместить нельзя —
  статус «распределить не удалось», причины по каждому стаду, **доказательство узкого места** и что можно изменить.
  Прежний быстрый жадный алгоритм — для сравнения (`node scripts/benchmark-optimizer.js`).
- пример: участок Б-С Кегена — 320 га пастбищного покрова − 47,1 га жилья и ферм (OpenStreetMap, буфер 100 м) = 272,9 га, NDVI 0,289 → 756 кг/га → … → **313 овец** за сезон (без вычета было 367; кнопка «Как рассчитано?»).
- где нельзя пасти: жильё, населённые пункты, фермы и скотные дворы, промзоны, кладбища и военные объекты из OpenStreetMap с буфером 0/100/250/500 м вычитаются из пастбищного покрова (`web/nograze.js`); это данные карты, а не кадастр и не решение акимата.

Надёжность — **две разные оценки**:
- качество спутникового измерения (одно правило для участков села и своих пастбищ): высокое — от 4 безоблачных дат, от 300 пастбищных пикселей 10 м и от 70 % покрытия;
  среднее — от 2 дат, 50 пикселей и 50 %; иначе низкое; без NDVI — нет данных;
- достоверность корма: пока коэффициент не проверен укосом, ёмкость и число голов — неподтверждённая оценка, даже при отличном снимке.

## Тесты

```bash
npm test
```

- `tests/engine.test.js`, `tests/plan.test.js` — формулы, инварианты плана (не больше допустимой ёмкости, распределено + дефицит = спрос, закрытые участки и участки без данных не используются, нет ложного «успеха», календарь без наложений), нет NDVI, нехватка корма и воды, права, дойные, невозможность распределения, окна сезона, чувствительность, точная граница, сценарии;
- `tests/model.test.js`, `tests/pipeline.test.js` — диапазоны параметров, качество снимка ≠ достоверность корма, классы WorldCover, облака, даты и повторы сцен, контуры, единицы площади, метаданные;
- `tests/api.test.js`, `tests/gemini.test.js`, `tests/bot.test.js` — вход, роли, чужие данные, поддельный NDVI, неверные параметры, повтор запроса, лимиты, ИИ при неполных данных, тревоги и дубли уведомлений;
- `tests/ui.test.js` — полнота казахского перевода, тексты для всех кодов, совпадение правил достоверности в README и коде;
- `npm run test:e2e` — путь пользователя в браузере на ПК и телефоне; `npm run test:net` — живые запросы к спутниковым данным (нужен интернет).

## Запуск у себя

```bash
python3 -m http.server 8765 --directory web          # сайт → http://localhost:8765
```

Бот и API: файл `.env` (не попадает в git) с `TELEGRAM_TOKEN=…` и по желанию `DEEPSEEK_API_KEY=…` (или `GEMINI_API_KEY=…`), затем `node bot.js`.
Пока бот работает на Render, локально его не запускайте: локальный запуск отключает webhook.

## Хостинг

- Сайт — GitHub Pages из ветки `gh-pages` (обновляется при каждом push в `main`).
- Бот и API — Render (`render.yaml`): веб-сервис + Key Value. Бесплатный сервер засыпает через 15 минут, первый ответ после паузы — до минуты.
- **Важно:** бесплатный Key Value на Render может потерять данные при перезапуске хранилища (аккаунты, профили, сценарии). Для реального использования нужен платный тариф с сохранением на диск или база данных.
- Ежедневная проверка снимков — `.github/workflows/daily-check.yml`. Пароль больше не нужен: GitHub Actions предъявляет
  OIDC-токен GitHub, сервер (`cronauth.js`) проверяет подпись GitHub, репозиторий, файл workflow и ветку `main`.
  `CRON_SECRET` (в Render и GitHub Secrets) остаётся запасным способом.
- Проверки в GitHub Actions: `tests.yml` — все тесты на каждом PR (в том числе WebKit — движок Safari, и реальные снимки);
  `live-check.yml` — проверка работающей системы: сайт, сервер, ИИ с настоящим ключом, страница бота (вручную и по понедельникам).
- PDF собирается библиотекой html2pdf.js из `web/vendor` (MIT), без внешнего CDN.

## Что реальное, а что условное

**Реальное:** NDVI по снимкам Sentinel-2, маска пастбищ ESA WorldCover (одни классы для села и своего контура), площади пастбищ, поиск сёл, расчёт по формулам выше, вход через Telegram и роли на сервере.

**Условное:** границы участков (секторы; в реальности — схема пастбищ акимата), демо-стада в примерах (всегда помечены «Пример»),
вода у села (предположение) и на дальних участках (водоём на карте — не проверенный водопой), права на участки (ввод хозяйства, не госреестр),
коэффициент биомассы, цена сена (30 000 ₸/т — пример). NDVI своего пастбища, посчитанный на сайте, сервер хранит с пометкой «не проверен».
Примеры (Бесколь, Кеген) — расчёт по реальным снимкам с условными стадами, а не полевая валидация в Бесколе и Прибрежном.
