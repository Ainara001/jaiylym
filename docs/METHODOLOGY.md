# Методология расчёта JAIYLYM (модель 2.1.0)

**Статус модели:** не подтверждена полевыми измерениями. Все числа ёмкости — оценки.

## 1. Что измерено, что посчитано, что предположено

| Величина | Источник | Тип |
|---|---|---|
| NDVI участка | Sentinel-2 L2A, медиана безоблачных летних дат | измерение спутника |
| Площадь пастбищного покрова | ESA WorldCover 10 м (2021) | измерение (классификация) |
| Биомасса, кг/га | формула ниже | расчёт по формуле |
| Доступный корм, кг | формула ниже | оценка модели |
| Число голов за сезон | формула ниже | оценка модели |
| Поголовье, участки хозяйства, вода «подтверждена / нет» | пользователь | ввод |
| Вода у села | модель | предположение |
| Водоём на карте | WorldCover класс 80 | измерение, но **не** пригодность водопоя |

## 2. Формула

```
biomass_kg_ha        = max(0, NDVI − ndvi0) × k_ndvi
available_forage_kg  = pasture_ha × biomass_kg_ha × util × forage_factor
capacity_au_days     = available_forage_kg / intake
capacity_au_season   = capacity_au_days / season_days                       — оценка по снимку
capacity_au_season   = min(оценка по снимку, предел по норме)                — если известна область
capacity_sheep       = capacity_au_season / au_sheep
```

Пример (Кеген, участок Б-С): 320 га, NDVI 0,289.
`max(0, 0,289 − 0,10) × 4000 = 756 кг/га` → `320 × 756 × 0,5 = 120 960 кг` → `120 960 / 11 = 10 996 усл. гол.·сут`
→ `10 996 / 150 = 73,3 усл. гол.` → `73,3 / 0,2 = 367 овец за сезон`. Тот же расчёт — кнопка «Как рассчитано?».

**Где нельзя пасти** (`web/nograze.js`): из пастбищного покрова вычитаются жильё и населённые пункты, фермы и скотные дворы,
промзоны, кладбища и военные объекты из OpenStreetMap (Overpass), перенесённые на сетку WorldCover, с буфером 0/100/250/500 м
(по умолчанию 100 м — допущение, санитарный разрыв). Место, отмеченное в OSM только точкой, — круг по типу места (оценка).
У Б-С Кегена с буфером 100 м: `320 − 47,1 = 272,9 га` → 313 овец вместо 367. Где карта OSM неполная, зон меньше реальных.

**Предел по норме нагрузки** (`web/norms.js`, с 2.1.0): `предел = pasture_ha / norm_ha_per_au × min(1, конец_периода / season_days)`.
Таблица — приложение к приказу МСХ РК № 3-3/332 в редакции от 09.12.2024 № 394, 253 строки, сверена с adilet (SHA-256 нормализованного текста
`96ebc939…`). Область — по OSM; тип пастбища и состояние выбирает человек, без выбора — самая мягкая норма области. Га на условную голову —
медиана трёх колонок (КРС, овца × 5, лошадь / 1,2), чтобы опечатка в одной ячейке не меняла расчёт. Область неизвестна — предела нет, это показано.
Зачем: у густой травы оценка по снимку выше нормы в разы (Бесколь: 20 819 овец по снимкам, 6 536 по мягкой норме СКО); у Б-С Кегена
(0,87 га на овцу при норме 0,5–4,0) предел не действует, 313 овец не изменились. Порог «меньше 30 % нормы» — ст. 14 Закона «О пастбищах», только для своих пастбищ.

## 3. Параметры (`web/model.js`)

| Параметр | По умолчанию | Диапазон | Единицы | Источник |
|---|---|---|---|---|
| `season_days` | 150 | 1–365, целое | сут | допущение: май–сентябрь |
| `intake` | 11 | 3–25 | кг СВ / усл. гол. / сут | справочная норма |
| `util` | 0,5 | 0,05–0,9 | доля | «съел половину — оставь половину» |
| `ndvi0` | 0,10 | 0–0,3 | NDVI | NDVI голой почвы, допущение |
| `k_ndvi` | 4000 | 500–12 000 | кг СВ/га на 1,0 NDVI | **не откалиброван** |
| `forage_factor` | 1 | 0,1–2 | множитель | поправка (засуха, сезон) не задана — данных нет |
| `max_load` | 1 | 0,1–1 | доля ёмкости | план не грузит участок больше 100 % |
| `au.sheep`, `au.goats` | 0,2 | 0,05–0,5 | усл. гол. | справочный коэффициент |
| `au.cattle` | 1 | 0,5–1,5 | усл. гол. | базовая единица |
| `au.horses` | 1,2 | 0,5–1,5 | усл. гол. | приказ № 3-3/332: га на лошадь = 1,2 га на КРС |
| `hay_dm` | 0,85 | 0,5–1 | доля СВ | справочное значение |
| `hay_price` | 30 000 | 0–1 000 000 | тенге/т | пример |

Слои: стандартные → откалиброванные (полевые, хранятся отдельно, с источником и датой) → пользовательские.
У каждого значения видно происхождение. Неверное значение отклоняется с причиной, а не заменяется молча.
Модель считается подтверждённой полем, только если `k_ndvi` взят из калибровки с отметкой «полевые укосы».
Тип растительности хранится, но коэффициентов не меняет: подтверждённых данных по типам нет. Тип пастбища по приказу меняет только предел нормы.

**Как откалибровать `k_ndvi`.** На 3–5 участках в день, близкий к снимку Sentinel-2: срезать траву с 1 м² на 3 площадках,
высушить до постоянного веса, взвесить. `k = биомасса_кг_га / (NDVI − ndvi0)`; взять медиану. Ввести в «Настройки → Полевая калибровка».

## 4. Статусы данных участка

- `no_data` — NDVI нет: ёмкость **неизвестна**, участок не используется в плане, показывается «нет данных»;
- `insufficient_quality` — NDVI есть, но качество снимка низкое;
- `estimated` — оценка по неоткалиброванной формуле (так сейчас у всех участков);
- `calibrated` — `k_ndvi` из полевой калибровки.

## 5. Две разные оценки надёжности

**Качество спутникового измерения** (одно правило для участков села и своих пастбищ):
высокое — от 4 безоблачных дат, от 300 пастбищных пикселей 10 м и от 70 % покрытия валидными пикселями;
среднее — от 2 дат, 50 пикселей и 50 %; иначе низкое; без NDVI — нет данных.
Пиксели считаются в разрешении Sentinel-2 (10 м = 0,01 га): пересчёт снимка мельче родного пикселя не увеличивает выборку.
Для сохранённых данных Кегена число пикселей не записано — оно оценено по площади и шагу сетки ~50 м (в метаданных есть предупреждение).

**Достоверность корма** — насколько обоснован перевод NDVI в сухую биомассу: без полевой калибровки — «не подтверждена»,
как бы хорош ни был снимок.

## 6. Земной покров ESA WorldCover

| Класс | Категория |
|---|---|
| 20 кустарник, 30 трава, 60 редкая растительность | потенциально пригодный пастбищный покров |
| 10 лес, 40 пашня, 50 застройка, 70 снег, 80 вода, 95 мангры | исключено |
| 90 водно-болотные травы, 100 мхи, 0 и неизвестные коды | неопределённо |

Одни правила для участков села и для контура фермера. Пастбищный покров ≠ право выпаса.
Класс 60 включает голую почву: он оставлен «пастбищным», как в сохранённом расчёте Кегена, а его NDVI близок к `ndvi0`,
поэтому корма по нему модель почти не даёт.

## 7. Спутниковая обработка

- B04 — красный, B08 — ближний ИК; NDVI = (B08 − B04) / (B08 + B04);
- маска SCL: оставляются только 4 (растительность) и 5 (голая почва); облака, тени, снег, вода, насыщение, no-data — отбрасываются;
- смещение +1000 для processing baseline ≥ 04.00, а если baseline не указан — для сцен с 25.01.2022;
- отбраковка яркости ≤ 0 и ≥ 20 000, NDVI вне [−1, 1];
- сцены с неверной датой, вне окна поиска или из будущего отбрасываются; повтор одного id — тоже;
- тайлы одной даты склеиваются в одно наблюдение;
- медиана по датам; ряд по датам — только если облака закрыли меньше половины пастбища;
- нет снимков: у села — понятная ошибка, у своего контура — `data_status: no_data`.
- вода по снимкам (`plotWater`): класс SCL 6; пиксель — устойчивая вода, если виден ≥ 2 раз и был водой ≥ половины из них
  (отсекает тени гор и лужи). Только для сравнения лет и ИИ — статус водопоя (§8) не меняет.
- прошлое лето (`buildSeason`, `compareSeasons`): те же участки, окно июнь–август года − 1; изменение NDVI < 5 % — «без изменений»;
  сравнение ненадёжно, если в каком-то году < 4 дат или NDVI есть меньше чем у половины участков. Кеген — заранее
  (`scripts/add_history.js`), остальные сёла — в фоне в браузере и в боте.

Единые метаданные (сайт, бот, PDF): `source, dataset, year, scene_dates, imagery_count, valid_pixel_fraction,
landcover_source, landcover_year, calculated_at, model_version, data_status, warnings`.

## 8. Водопой

`confirmed` (пользователь), `satellite` (водоём на карте), `assumed` (у села, модель), `modeled` (сценарий), `unknown`, `absent` (пользователь).
По умолчанию план использует `confirmed / satellite / assumed / modeled` и предупреждает, что вода не проверена на месте;
политика `confirmed_only` — только подтверждённые. Моделирование водопоя показывает, какие участки начинают использоваться,
как меняется дефицит и какие ограничения остаются. Это не рекомендация строить скважину.

## 9. Распределение

**Алгоритм по умолчанию — оптимизатор `fair-optimal-v2`** (подробно — `docs/INNOVATION.md`, сравнение — `docs/BENCHMARK.md`):
1) max-min справедливость по доле обеспеченности хозяйств (прогрессивное заполнение на max-flow); 2) при этом максимум корма
(равен точной границе); 3) при этом минимум перегона (поток минимальной стоимости, км от домашнего участка, штраф 10 км
за ближний участок для не дойного стада); 4) при тех же долях — меньше перегонов и коротких стоянок: склейка, обмен кусками между стадами
(нагрузка участков не меняется) и запрет мелких пар с пересчётом потока; итог не хуже исходного по [перегоны, короткие стоянки, км];
5) календарь с ремонтом конфликтов окон: ближние участки целыми группами на весну и осень, единственный ближний режется пополам только при ≥ 2 × 14 дней.
**Отдых участка** (ввод): не пасти первые/последние N дней сезона — окно выпаса участка. **Приоритет хозяйства** (ввод, 1 / 1,5 / 2):
при нехватке доля растёт быстрее (взвешенный max-min); решение о приоритете — координатора или акимата, не модели.
Шаги 1–3 оптимальны для задачи без календаря и правила «2 недели»; итоговый план проверяется теми же инвариантами.
При дефиците показывается **доказательство узкого места** (минимальный разрез).

Прежний **быстрый жадный алгоритм** (`greedy-heuristic-v2`) остаётся в настройках и в сравнении «Что если?»; он не оптимизатор.
**Критерий обоих:** минимум неудовлетворённой потребности в голово-днях при соблюдении всех ограничений; у оптимизатора — ещё справедливость и перегон.

Ограничения: участок используется стадом, только если у него есть NDVI, пригодная по введённым данным вода, он не закрыт,
открыт в период расчёта, входит в список участков хозяйства (если список указан), а для дойного стада — ближний;
загрузка не выше `max_load × ёмкость`; дни на участке не больше длины окна.

Порядок жадного алгоритма: дойные первыми, затем от малых стад к большим; сначала дальние участки (жайлау), ближе к дому;
куски не меньше 2 недель, затем добор остатков. Календарь: весна — ближние, лето — дальние, осень — ближние;
сегменты с окнами ставятся только в окно; что не поместилось в календарь — возвращается в дефицит.

**Проверка эвристики:** точная нижняя граница дефицита — максимальный поток «стада → участки» (алгоритм Диница)
с теми же ограничениями, но без правила «не меньше 2 недель» и календаря. Разница показывается во вкладке «Что если?».

**Статусы:** `feasible` (всё распределено), `partially_feasible`, `infeasible` (ни одного допустимого участка),
`no_demand`. Для каждого стада с дефицитом — причина (`capacity / no_allowed_plots / calendar`) и исключённые участки по причинам.

**Инварианты (тесты):** загрузка ≤ допустимой; распределено + дефицит = спрос; закрытые участки и участки без NDVI
не используются; ресурс не распределён дважды; нет отрицательного корма; нет «успеха» при дефиците или нарушениях;
календарь 1…сезон без наложений, дни без корма помечены.

## 10. Сценарии

«Что если?»: как сейчас, план, +водопой, без самого загруженного участка, корма −20 %, скота +20 %, сезон +30 дней,
осторожные и оптимистичные допущения. Сценарии допущений: осторожный — `util × 0,8`, `k_ndvi × 0,75`;
оптимистичный — `util × 1,2` (не выше 0,9), `k_ndvi × 1,25`. Это **не** доверительный интервал.

## 11. Тревоги в боте

Снижение NDVI ≥ 0,05 или ≥ 12 % к медиане прошлых наблюдений на **одном** снимке — «Возможно снижение травы»;
на **двух подряд** — «Внимание: трава убывает». Повторный запуск планировщика не рассылает то же уведомление.

## 12. Ограничения

Не учитываются: поедаемость видов трав, отрастание за сезон, засуха текущего года, вытаптывание, снег, породы,
реальные границы пастбищ акимата, правовой статус земли, качество воды. Демонстрация Кегена — реальные снимки
и условные стада; это не полевая валидация проблемы в Бесколе и Прибрежном.
