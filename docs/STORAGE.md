# Хранение данных: риски и план для пилота

**Сейчас.** `render.yaml`: веб-сервис и Key Value на тарифе `free`, `maxmemoryPolicy: noeviction`.
Бесплатный Key Value на Render не гарантирует сохранность при перезапуске хранилища: аккаунты, профили хозяйств,
пастбища и сценарии могут пропасть. Сохранность пользовательских данных **не обещается**.
Сценарии гостя и интервью хранятся только в браузере и пропадают при очистке браузера.

Настройки Render из этой среды не проверялись (сеть закрыта); выводы — по `render.yaml` и README.

**Для пилота (предложение, миграция не выполнялась):**
1. Платный Key Value с сохранением на диск **или** управляемый PostgreSQL; `store.js` уже изолирует хранилище — добавить второй адаптер.
2. Ежедневная выгрузка состояния (JSON) в отдельное хранилище с доступом только у владельца.
3. План миграции: заморозка записи → выгрузка `bot_state` → загрузка в новое хранилище → сверка числа пользователей,
   хозяйств, пастбищ и сценариев → переключение `REDIS_URL`/`DATABASE_URL` → наблюдение неделю. Делать с отдельным разрешением.
